# Конспект по нотации BPMN 2.0

## 1. Назначение BPMN

BPMN (Business Process Model and Notation) — международный стандарт графического описания
бизнес-процессов, разработанный организацией OMG. Его цель — дать единый, однозначно
читаемый язык, на котором бизнес-аналитики, разработчики и руководители описывают, как
выполняется процесс: в каком порядке идут действия, кто их выполняет и при каких условиях
поток уходит в ту или иную ветку. В отличие от произвольных блок-схем, каждый элемент BPMN
имеет строгое семантическое значение, поэтому диаграмму одинаково прочитает любой специалист,
знакомый с нотацией. В профессиональной практике BPMN используют для проектирования
информационных систем, описания регламентов и поиска узких мест в процессах.

## 2. Таблица элементов нотации

| Элемент | Обозначение | Семантика | Пример применения |
|---------|-------------|-----------|-------------------|
| Start Event | тонкий круг | Запуск процесса | «Поступила заявка продавца» |
| End Event | жирный круг | Завершение ветки процесса | «Магазин активирован» |
| Intermediate Event | двойной круг | Событие в ходе процесса (таймер, сообщение, ошибка) | Ожидание оплаты 3 дня |
| Task (Задача) | прямоугольник со скруглением | Атомарное действие | «Проверить данные заявки» |
| User Task | прямоугольник с иконкой человека | Действие выполняет человек | «Менеджер проверяет документы» |
| Service Task | прямоугольник с иконкой шестерёнки | Автоматическое действие системы | «Создать поддомен магазина» |
| Sub-Process | прямоугольник с маркером «+» | Составная функция, раскрываемая отдельно | «Настройка магазина» |
| Gateway (шлюз) | ромб | Разветвление/слияние потоков | Выбор «заявка одобрена / отклонена» |
| Sequence Flow | сплошная стрелка | Поток управления внутри пула | Связь двух задач |
| Message Flow | пунктирная стрелка | Поток сообщений между пулами | «Письмо покупателю» |
| Pool / Lane | рамка / дорожка внутри рамки | Участник / роль внутри участника | Пул «Платформа», дорожка «Поддержка» |
| Text Annotation | скобка с текстом | Пояснение, без семантики | Комментарий к задаче |

## 3. Типы шлюзов (Gateway)

| Шлюз | Условие применения | Пример из практики | Типичная ошибка |
|------|--------------------|--------------------|-----------------|
| XOR (исключающий) | Выбирается ровно одна ветка из нескольких | «Заявка одобрена» / «Заявка отклонена» | Не подписаны условия на исходящих потоках |
| OR (включающий) | Может сработать одна или несколько веток одновременно | Уведомить по e-mail и/или SMS | Забыт шлюз слияния, ветки не сходятся |
| AND (параллельный) | Все ветки выполняются параллельно | Одновременно создать поддомен и сгенерировать QR-знаки | Использован вместо XOR там, где нужен выбор |
| Event-based | Дальнейший путь зависит от того, какое событие наступит первым | Пришёл ответ / истёк таймер | Перепутан с XOR по данным |

## 4. Типы подпроцессов

- **Collapsed Sub-Process (свёрнутый)** — изображается одним прямоугольником с маркером «+»;
  его внутренняя логика раскрывается на отдельной диаграмме (отдельном листе). Используется,
  когда нужно скрыть детали и не загромождать основную схему.
- **Expanded Sub-Process (раскрытый)** — детали показаны прямо внутри увеличенного
  прямоугольника на той же диаграмме. Подходит для небольших подпроцессов, когда детали важно
  видеть в общем контексте.

Выбор: если подпроцесс крупный или повторяется — берут Collapsed (детали на отдельном листе);
если он маленький и важен для понимания общей картины — Expanded. На итоговой диаграмме SellWhy
используются Collapsed-подпроцессы, раскрытые на отдельных листах, чтобы основная схема
оставалась читаемой.

## 5. Авторский чек-лист проверки диаграммы

1. У процесса есть ровно одно стартовое событие в каждом пуле, и оно подписано.
2. Каждая ветка процесса заканчивается своим End Event с осмысленной подписью результата.
3. Все задачи названы в глагольной форме («Проверить заявку», а не «Проверка заявки»).
4. У каждого шлюза XOR/OR подписаны условия на всех исходящих потоках.
5. Между разными пулами идёт только Message Flow (пунктир), Sequence Flow — внутри пула.
6. Нет «висящих» стрелок: каждая стрелка имеет источник и приёмник.
7. Каждый разветвляющий шлюз имеет парный сливающий (или ветки корректно завершаются).
8. Задача в дорожке того участника, который её реально выполняет.
9. Подпроцесс помечен маркером «+» и раскрыт на отдельном листе.
