# Упражнения по IDEF0

Исходник всех диаграмм — `exercises_idef0.drawio` (draw.io, по листу на диаграмму).
PNG — экспорт: одно упражнение = один файл; если в упражнении несколько диаграмм, они идут сверху вниз.

| № | Файл | Что отрабатывается | Диаграммы |
|---|------|--------------------|-----------|
| 1 | ex01.png | Один блок «Сформировать отчёт» и четыре типа дуг ICOM | блок |
| 2 | ex02.png | Контекстная диаграмма функции «Обработать заказ клиента» | A-0 |
| 3 | ex03.png | Первая декомпозиция на три блока: выход A1 → вход A2 → вход A3 | A0 |
| 4 | ex04.png | «Управлять персоналом», 4 блока: выход A1 одновременно управление A3; туннельная дуга «1С:ЗУП» | A0 |
| 5 | ex05.png | Ветвление (выход A1 → вход A2 и управление A4) и слияние дуг (счёт + накладная → документы поставки) | A0 |
| 6 | ex06.png | «Управлять складом»: контекст и декомпозиция на 4 блока, согласованность границ | A-0, A0 |
| 7 | ex07.png | Те же блоки A0 с конкретными механизмами и особым управлением для A1 (Инструкция П-6) | A0 |
| 8 | ex08.png | Второй уровень: блок A2 «Разместить и хранить товары» → A21, A22, A23 | A-0, A0, A2 |
| 9 | ex09.png | Реальный процесс SellWhy из задания 1 «Обработать заказ покупателя» | A-0, A0 |
| 10 | ex10.png | Развитие упр. 9: декомпозиция блока A2 «Провести оплату заказа» | A-0, A0, A2 |

**Обозначения.** I — вход (слева), C — управление (сверху), O — выход (справа), M — механизм (снизу).
Коды I1, C1, O1, M1 на граничных дугах связывают диаграмму с дугами родительского блока.
Скобки `( )` у конца дуги — туннельная дуга: она есть только на этом уровне и не показывается на родительской диаграмме.
